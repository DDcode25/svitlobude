# Техническое задание: Telegram-бот уведомлений об отключениях электроэнергии

## 1. Цель

Разработать Telegram-бота, который работает по всей подконтрольной Украине. Бот получает графики плановых отключений электроэнергии от операторов систем распределения (облэнерго, ДТЕК) и уведомляет пользователя об отключениях в его группе (очереди).

Бот должен помогать пользователю быстро узнать, когда ожидается отключение и когда планируется восстановление электроснабжения. Он не гарантирует фактическое время отключения или включения: расписание может изменяться оператором, а при аварийных отключениях (ГАВ) графики не действуют.

## 2. Область применения и исходные допущения

- Канал взаимодействия: Telegram.
- Охват: все регионы, для которых доступен поддерживаемый источник данных (см. раздел 3). Луганская область и оккупированные территории не входят в охват.
- Единого государственного API с графиками нет. Укренерго объявляет только количество применяемых очередей, а расписание по группам публикует каждый оператор у себя. Поэтому бот работает с несколькими источниками через отдельные модули (адаптеры).
- Основная сущность подписки — **регион + оператор + группа**. Если источник поддерживает поиск по адресу, подписка дополнительно хранит адрес, по которому группа была определена.
- Схема групп отличается между регионами: обычно это 6 очередей по 2 подочереди (`1.1` … `6.2`), но в Киеве сейчас 60 групп (`1.1` … `60.1`), назначенных по домам. Количество и обозначения групп нельзя зашивать в код; они приходят из источника.
- Бот не управляет электроснабжением и не принимает заявки на его восстановление.
- Бот сообщает только данные, доступные в источнике, и показывает время последнего изменения графика и время последней успешной проверки.
- Время отображается в часовом поясе `Europe/Kyiv`.

## 3. Источники данных

Подробный обзор источников с проверенными эндпоинтами — в [sources/outage-data-sources.md](./sources/outage-data-sources.md). Ниже — минимум, необходимый для реализации.

### 3.1 Типы источников

| Тип | Пример | Статус |
|---|---|---|
| Официальный API оператора | Yasno (Киев, Днепр), Львовобленерго (`api.loe.lviv.ua`) | Официальный, без авторизации и документации |
| JSON-зеркала сообщества | `Baskerville42/outage-data-ua`, `yaroslav2901/OE_OUTAGE_DATA` и совместимые | Неофициальные парсеры официальных сайтов, единый формат `fact` / `preset` / `GPVx.y` |
| Собственный парсер сайта оператора | Волынь, Черновцы, Николаев, Кировоград, Херсон, Сумы, ДТЕК Донецк | Требует разработки, этап 2 |

### 3.2 Покрытие на старте

- **Официальные API:** Киев и Днепр (Yasno), Львовская область (Львовобленерго).
- **JSON-зеркала:** Киевская, Днепропетровская, Одесская, Черкасская, Черниговская, Полтавская, Харьковская, Житомирская, Ивано-Франковская, Ровенская, Закарпатская, Хмельницкая, Тернопольская, Запорожская, Винницкая области.
- **Без готового источника:** Волынская, Черновицкая, Николаевская, Кировоградская, Херсонская, Сумская, Донецкая (ДТЕК ДЕМ).

Если для региона есть официальный API, он используется как основной источник, а зеркало — как резервный.

### 3.3 Требования к адаптерам

- Каждый адаптер реализует общий интерфейс: список регионов и операторов, список групп, расписание по группам на сегодня и завтра, а также, если источник это поддерживает, поиск группы по адресу.
- Адаптер возвращает данные во внутренней модели (раздел 5.3) и не содержит логики Telegram.
- Для каждого источника настраиваются: частота опроса, таймауты, порог устаревания, приоритет (основной или резервный) и флаг включения.
- Источники без явной лицензии или с ограничениями использования отмечаются в конфигурации; перед запуском их условия должны быть проверены.

## 4. Пользовательские сценарии

1. Пользователь запускает бота командой `/start`.
2. Бот объясняет назначение сервиса и предлагает выбрать регион (область или город).
3. Если в регионе несколько операторов (например, ДнЕМ и ЦЕК в Днепре), бот предлагает выбрать оператора.
4. Бот определяет группу одним из способов:
   - **по адресу**, если источник это поддерживает (Yasno, ДТЕК, Львовобленерго): пользователь вводит улицу, выбирает её из найденных вариантов, затем выбирает дом, и бот получает группу у источника;
   - **вручную**: пользователь выбирает группу из списка, который вернул источник. Бот подсказывает, где на сайте оператора узнать свою группу.
5. Бот подтверждает подписку и показывает регион, оператора, группу и адрес, если он указан.
6. Бот отправляет уведомление перед плановым отключением, а также сообщает об изменении или отмене расписания и о переходе на аварийные отключения.
7. Пользователь запрашивает текущее расписание и получает интервалы для своей группы.
8. Пользователь может изменить регион, адрес или группу, настройки уведомлений или отписаться.

## 5. Функциональные требования

### 5.1 Команды

- `/start` — начать работу, показать краткое описание и настроить подписку.
- `/schedule` — показать расписание на сегодня и завтра для выбранной группы.
- `/settings` — изменить регион, адрес, группу и параметры уведомлений.
- `/help` — показать справку и ограничения сервиса.
- `/stop` — отключить уведомления; команда не должна удалять данные, которые необходимы для работы других пользователей.

Названия команд могут быть локализованы, но бот должен поддерживать указанные команды Telegram либо документированные эквиваленты.

### 5.2 Настройка подписки

- Бот сохраняет Telegram ID пользователя и параметры подписки: регион, оператора, группу и, если указан, адрес.
- Списки регионов, операторов и групп формируются из подключённых и включённых источников, а не задаются вручную.
- Бот проверяет введённые значения. При неизвестном значении он объясняет ошибку и предлагает повторить выбор.
- До успешного выбора группы бот не отправляет пользователю уведомления об отключениях.
- Пользователь может заменить или удалить свою подписку.
- Если подписка определена по адресу, бот периодически перепроверяет группу этого адреса. При изменении группы он обновляет подписку и сообщает об этом пользователю.
- Если источник региона отключён или перестал публиковать группу пользователя, бот сообщает об этом, а не молчит.

### 5.3 Получение и обработка расписания

- Внутреннее представление расписания содержит как минимум:
  - регион, оператора, группу (строковый идентификатор, например `3.2` или `20.1`) и дату;
  - интервалы с началом и концом с точностью не хуже 30 минут; источники отдают как часовые слоты с половинами (`first`/`second`), так и минутные интервалы;
  - тип интервала: отключение подтверждено, возможно или не запланировано;
  - статус дня: график действует, график ожидается, аварийные отключения (график не действует) или неизвестно;
  - время изменения графика у источника и время последней успешной проверки.
- Время, даты и часовой пояс источника корректно преобразуются в `Europe/Kyiv`, включая переход на летнее и зимнее время.
- Если источник не предоставляет интервал или статус, бот не придумывает отсутствующие значения.
- Недельный «вероятный» график (`preset`, `probable-outages`) хранится отдельно от графика на сегодня и завтра. Пользователю он показывается только с явной пометкой «возможные отключения».
- Частота запросов соответствует ограничениям источника и настраивается без изменения бизнес-логики.

### 5.4 Контроль свежести данных

- Для каждого источника и региона бот хранит время последней успешной проверки и время последнего изменения графика.
- Данные считаются **устаревшими**, если последняя успешная проверка старше порога источника. Порог настраивается, начальное значение — 1 час.
- Если график давно не менялся, но источник успешно проверяется, это не ошибка. В ответе пользователю указывается дата последнего изменения.
- Если данные зеркала старше 2 суток и есть подозрение, что парсер не работает (например, зеркало отстаёт от официального источника), регион помечается как «данные под вопросом». Пользователь видит предупреждение, рассылка новых уведомлений приостанавливается.
- Если основной источник недоступен, бот переключается на резервный, если он настроен, и помечает в ответе, из какого источника получены данные.

### 5.5 Уведомления

- Бот отправляет уведомления только пользователям, подписанным на соответствующие регион, оператора и группу.
- Пользователь получает уведомление о предстоящем отключении заранее. Время предупреждения настраивается; начальное значение согласуется до запуска.
- При существенном изменении или отмене уже опубликованного интервала бот отправляет отдельное уведомление.
- При переходе региона на аварийные отключения бот сообщает подписчикам, что график временно не действует.
- Повторная обработка одного и того же обновления не приводит к повторной отправке одинакового уведомления.
- В сообщении указываются регион, группа, интервал отключения, тип и статус расписания и время последнего изменения графика.
- Пользователь может отключить уведомления, не теряя возможности запросить расписание вручную.
- Рассылка рассчитана на большое количество подписчиков по всей стране и соблюдает ограничения Telegram на частоту отправки.

### 5.6 Тексты сообщений

- Сообщения краткие, на русском языке в первой версии.
- Формулировки отличают плановый график от вероятного и от аварийного режима.
- Если данные получены из неофициального зеркала, бот указывает, что они получены из открытой копии сайта оператора и могут отставать.

## 6. Нефункциональные требования

### 6.1 Технологии

- Язык: Python.
- Работа с Telegram: библиотека [Telethon](https://docs.telethon.dev/) в режиме бота (`client.start(bot_token=...)`).
- Для Telethon, помимо токена бота, нужны `api_id` и `api_hash` приложения с [my.telegram.org](https://my.telegram.org).
- Файл сессии Telethon (`*.session`) хранится вне репозитория и устойчиво между перезапусками.
- При рассылке бот обрабатывает `FloodWaitError`: ждёт указанное время и продолжает отправку, не теряя очередь уведомлений.

### 6.2 Общие требования

- Секреты (Telegram Bot Token, `api_id`, `api_hash`) хранятся в переменных окружения или менеджере секретов и не попадают в репозиторий, логи или сообщения.
- Бот корректно переживает временную недоступность Telegram или источника данных и повторяет операции с ограниченным интервалом и числом попыток.
- Ошибки получения и разбора расписания журналируются с указанием источника и региона, без токенов и избыточных персональных данных.
- Данные подписок хранятся устойчиво между перезапусками.
- Адрес пользователя хранится только для повторной проверки группы и удаляется вместе с подпиской.
- Доступ к данным пользователей ограничивается необходимостью отправки уведомлений и управления их подписками.
- Предусмотрена возможность остановить рассылку при ошибочных данных — отдельно по каждому региону или источнику.
- Реализация соблюдает условия использования и ограничения частоты запросов каждого источника. Адресные запросы к источнику кэшируются.
- Интерфейс остаётся понятным при отсутствии расписания, неизвестной группе, неподдерживаемом регионе или устаревших данных.

## 7. Обработка ошибок и крайние случаи

- **Источник недоступен:** не отправлять выдуманное расписание; переключиться на резервный источник, если он есть; при запросе сообщить о проблеме и показать время последней успешной проверки.
- **Источник вернул пустой график:** сообщить, что расписание для группы не опубликовано, а не трактовать отсутствие данных как отсутствие отключений.
- **Аварийные отключения:** сообщить, что графики временно не действуют, и не отправлять напоминания по плановому графику.
- **Источник изменил формат:** зафиксировать ошибку разбора, не рассылать некорректные интервалы, пометить регион как «данные под вопросом».
- **Данные зеркала устарели:** см. раздел 5.4.
- **Интервал изменился или отменён:** обновить ранее сохранённое состояние и отправить уведомление подписчикам этой группы.
- **Изменилась схема групп региона** (появились или исчезли группы): сообщить затронутым пользователям и предложить заново выбрать группу или указать адрес.
- **Адрес не найден у источника:** предложить уточнить написание или выбрать группу вручную.
- **Регион не поддерживается:** сообщить об этом и предложить подписаться на уведомление о подключении региона.
- **Пользователь заблокировал бота:** прекратить повторные отправки этому пользователю и отключить его подписку согласно возможностям платформы.
- **Нет группы в настройках:** запросить её выбор до отправки уведомлений.
- **Дублирующиеся данные:** дедуплицировать интервалы и уведомления по устойчивому идентификатору или нормализованному содержимому.

## 8. Этапы и границы MVP

### Этап 1 (MVP)

- Адаптер Yasno (официальный, с поиском по адресу) для Киева и Днепра.
- Адаптер JSON-зеркал (формат `outage-data-ua`) для остальных регионов из раздела 3.2.
- Адаптер Львовобленерго, если его формат позволяет надёжно получить интервалы; иначе Львов на этапе 1 обслуживается через зеркало.
- Telegram-бот с личными подписками, выбором региона, оператора и группы, а для Yasno — выбором по адресу.
- Просмотр расписания на сегодня и завтра.
- Уведомления о предстоящем отключении, изменениях, отмене и аварийном режиме.
- Контроль свежести данных и отключение рассылки по региону.
- Хранение подписок, базовые логи и конфигурация через переменные окружения.

### Этап 2

- Собственные парсеры для регионов без готового источника.
- Поиск по адресу через сайты ДТЕК и Львовобленерго.
- Поддержка украинского языка.

### Не входит

- Заявки оператору.
- Гарантирование фактического времени отключения или восстановления.
- Определение фактического наличия света (мониторинг устройствами, как в СвітлоБот).
- Групповые чаты, платежи и персональные прогнозы.
- Оккупированные территории.

## 9. Критерии приёмки

1. Новый пользователь может запустить бота, выбрать регион и группу (или адрес, если источник это поддерживает) и увидеть подтверждение подписки.
2. Для Киева пользователь может найти свою группу по улице и дому.
3. Списки групп соответствуют источнику региона: например, 60 групп для Киева и 12 подочередей для регионов со схемой 6×2.
4. Пользователь может запросить расписание только для своей группы и получить понятный ответ при отсутствии опубликованных данных.
5. Уведомление о новом интервале отправляется подписчикам нужных региона и группы и не отправляется подписчикам других групп или регионов.
6. Изменение, отмена интервала и переход на аварийные отключения обнаруживаются; пользователь получает соответствующее уведомление.
7. Повторная обработка одних и тех же данных не создаёт дублирующих уведомлений.
8. При недоступности или устаревании источника бот не выдаёт старые данные за актуальные и показывает время последнего обновления.
9. Отключение одного региона или источника не влияет на работу остальных.
10. Пользователь может изменить подписку и отключить уведомления.
11. Перезапуск бота не теряет подписки и состояние, необходимое для предотвращения дублирования уведомлений.
12. Токен, `api_id`, `api_hash`, файл сессии и другие секреты отсутствуют в исходном коде, логах и репозитории.
